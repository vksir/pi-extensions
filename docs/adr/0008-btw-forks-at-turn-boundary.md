# /btw 在 agent 忙碌时回退到上一个完整 turn 再 fork

`/btw` 的 fork 源是当前会话文件。pi 的会话文件是 append-only 的，一条消息只在 `message_end` 时才 `appendMessage` 落盘（`agent-session.js` 的 `_handleAgentEvent`），而 `SessionManager.forkFrom` 逐行原样复制、不做任何修整。两者相遇的后果是：turn 还在跑时敲 `/btw`，fork 出去的新会话会继承一个**未完成的 turn**——

- 模型正在流式输出：文件末尾是本轮 user 消息（已落盘）而没有回答，新会话看到「用户问了问题没答」，紧接着又是 `/btw` 的消息；
- 工具正在执行：文件末尾是带 `toolCall` 的 assistant 消息，没有对应 `toolResult`（排查过 pi 自己的 #11227：未配对的工具调用/结果会让下一次请求失败）；
- 屏幕上的那半截回复根本没落盘，新会话里不存在。

新 pi 会把这半截状态当成自己的完整过去，从第一句话起就跑偏；原会话随后做完的工作在 fork 里永远缺席。

## 决策

- **忙碌时截断到最后一个完整 turn 边界**：`ctx.isIdle()` 为假时，不直接 fork 原文件，而是先经 `lib/session-snapshot.ts` 生成一份快照再交给 `pi --fork`。空闲时行为不变，仍 fork 原文件。
- **边界 = 不含工具调用的 assistant 消息**：从文件最后一条 entry（pi 加载时当 leaf）沿 `parentId` 回溯当前分支，从末端向前找到第一条 content 里没有 `toolCall` 的 assistant 消息，保留到它为止。带 `toolCall` 的 assistant 只是 turn 中途的一步，不能当边界；找不到（第一轮就分派）则快照只剩 header，等价于全新会话——这与「当前会话本来就还没有完整历史」一致。
- **快照只写 header + 当前分支前缀**：旁支、挂在被丢弃位置的 label / 模型切换等 entry 一并舍弃，保证输出文件的 `parentId` 链自洽。解析时跳过空行与坏行——会话正在写，读到半截 JSON 尾行是正常现象。
- **快照写系统临时目录且不删**：`<tmp>/pi-btw-fork/<会话名>-<pid>-<random>.jsonl`。新 pi 是另一个进程，何时复制完不可知，删早了会毁掉 fork；单文件很小，留着无妨。源会话只读。
- **读快照失败就拒绝分派**：读不了会话文件时用 error 通知说明原因、不启动新标签——宁可这次不分派，也不产生上下文错乱的会话。
- **反馈里说明回退**：成功通知附「本轮尚未结束，已回退到上一个完整轮次，丢弃 N 条未完成记录」，用户能知道自己 fork 到了哪个点。

## 被否决的选项

- **忙碌时直接拒绝**：改动最小，但打断用户「顺手分派」的意图，而且用户多半正要趁本轮跑着时并行做事。
- **排队到 `agent_settled` 再 fork**：fork 点天然干净（完整 turn 结束），实现也省（`pi.on("agent_settled")`），但新标签要等本轮跑完才出现——与 `/btw` 的并行价值冲突，且本轮可能很长。
- **原样 fork 再让新 pi 自己「理解」半截历史**：这正是要修的 bug；模型没有足够信息判断哪半句属于别人未完成的工作。
- **截断到「最后一条消息」而非 turn 边界**：turn 内可能有完整落盘的 toolResult 序列，但站在模型角度仍是「自己正在中途执行任务」，紧接着的 `/btw` 消息会被当成对当前流程的回应，仍然混乱。

## 后果

- 忙碌时 fork 出的会话丢掉本轮全部进展（通常是一个 user 消息，或一次未完成的工具调用），新 pi 从上一轮结束处接续。这是有意的取舍：干净的历史比最新但残破的历史更有用。
- 临时快照目录会缓慢积累小文件；按会话名 + 随机名可辨认，可手动清理。
- 空会话或已停在完整边界的会话不产生快照（此时 `snapshotAtTurnBoundary` 返回 undefined），fork 路径与空闲时完全一致。
- 被丢弃尾部里的 `model_change` / `thinking_level_change` / 会话名 / label 等非消息 entry 也不进快照：它们挂在被裁掉的链上，保留会让 `parentId` 悬空；新会话据此回落到更早的模型或思考级别。只在忙碌时发生，且丢弃范围通常只有一两条。
- 与 ADR-0004 的消息 argv 通道正交：快照只替换 `--fork` 的参数值，消息仍走 `--` 之后的 argv。
