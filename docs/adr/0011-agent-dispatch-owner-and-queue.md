# agent 之间按「发起人 + 排队」派发，回信由模型自己 send

> **部分被取代**：`ask` 已改名 `send`，收工自动回发与 `result` 位、崩溃 / 排队 / blocked 通知均已删除，见 [ADR-0012](0012-agent-replies-are-sends.md)。本文件里「发起人（原派活人）+ 排队」的派发规则仍然有效，其中「派活人」现在只决定忙时插话还是排队、不承担回信职责。

## 背景

`pi-herdr-agent` 原来的消息模型有三处结构性问题：

1. **`ask` 与 `steer` 是两个动作，各自带状态前置检查**：`ask` 只允许发给 `idle` / `done`，忙就报错；`steer` 只允许发给 `working`，闲就报错。模型每次都要先判断对方状态，判断错就是一条错误。
2. **并发提问会被拒**：接收方进程里只有一个 `pendingAsker`，A 和 B 同时问 C，后来的那个立刻收到 `Busy: another request is already pending.`。多 agent 协作里这是常态，却做成了错误。
3. **回复语义挂在「当轮 asker」上**：只活在内存里，模型既看不见也控制不了；而「让模型自己调 reply」又要引入强制回复机制（`agent_before_settle` 续轮、欠账本、兜底回发），复杂度远高于收益。

> 本条 ADR 取代 [0007](0007-herdr-subagents-live-in-hc-terminal-tree.md) 中「结果按 asker 回发」与消息信封（`kind=ask|steer|result`）的决策；终端树、身份注入、id 推导等部分不变。

## 决策

- **一个动作发消息**：`agent_job` 只保留 `list` / `ask` / `stop`。`ask` 不检查对方状态，也不传 `if`。
- **一批轮次一个派活人**：叫醒这一轮的那条消息的发送方。轮次进行中只有它能插话（pi 原生 steer）。
- **其他人排队**：非派活人发来的消息在 `input` 里被 `{ action: "handled" }` 吞掉，不进上下文、按发送方聚合成一条，位置不变。
- **收工自动回发**：扩展把本轮最后一段 assistant 文本发回给派活人，模型不参与。只有 `ask` 起的轮次回发；自动回发本身与人打字都不回发。
- **自动回发用 `result` 位标记**：`<agent id "name" result>`。收到它的一方不排队、不回发。
- **首行合一**：`<agent id "name">` 既是传输标记也是模型可见的来源行，不再剥离，也不再携带发送方地址（寻址一律用 id）。
- **崩溃要交代**：`session_shutdown(quit)` 时给派活人发一条「退出了，没来得及回答」，队列里每人一条「你那条没做」。
- **`stop` 先礼后兵**：先发 `ctrl+d` 请对方自己退出（每下宽限 5 秒，最多两下），宽限内没走才 `hc.kill`。硬杀跳过 `session_shutdown`，上一条的通知就永远发不出去 —— 这是 E2E 实测出来的：单纯 `hc.kill` 时通知一条也没到。
- **可见范围收窄**：`agent_job list` 只返回自己、一级父、一级子、兄弟；人看的 `/agent list` 保留全景。

## 被否决的选项

- **让子 agent 自己调 `send` / `reply` 回消息**：模型会忘，于是需要强制回复机制（`agent_before_settle` 续轮 + 欠账本 + 兜底回发）。兜底那一步等价于「harness 回发」，却多背了一套状态；而且 A、B 同时问 C 时，`reply` 到底回给谁本身就有歧义。
- **保留 `steer` 动作**：忙时插入、闲时起轮，本来就是同一个动作的两种表现，交给接收方判断即可。
- **用 `<hc from="…">` 运输层代替自己的首行**：API 的 `terminal.send` 不套这层包装，只有 CLI 才有。
- **把派活人写进 label 让第三方可见**：违反 0007 的「label 不承担可变语义」，还得读写清理。放弃。
- **`interrupt`（打断）**：两版都不可行——带原因的消息要等当前工具跑完才派发，而卡在长工具里正是要打断的场景；`hc.keys` 发 Esc 则必须靠 label 交接原因，违反同上那条。
- **`peek`（读对方实时状态）**：要读会话文件尾部、沿 `parentId` 走当前分支、剥掉 thinking / base64 图片 / system 提示词等噪音（实测噪音占文件体积 88%），复杂度远大于收益。
- **结果回发不触发新轮次**：派活人空闲时永远等不到结果，正是要消灭的死锁。

## 后果

- 多 agent 同时派活不再有「忙」这个错误；C 串行处理，各自收到各自的回复。
- 队列只在进程内存里：崩溃由 shutdown 通知兜底，resume 后未处理的消息不恢复（已知缺口）。
- 被中止（Esc）时只回一句 `Run aborted.`，队列不动、不自动开工；队列非空则不进入空闲销毁，靠人或下一次消息重新启动。
- 可见范围收窄后，跨层（爷爷、侄子）不可见，只能逐级转达或由人介入。
- 每轮多一次 `hc.list()`：回发要按 id 反查终端地址。命名管道的开销可以忽略。
